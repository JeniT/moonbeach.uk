How to preview the website on your own computer, look around, and make changes. Allow about 20 minutes the first time. After that, it's one double-click.

1. Unzip the folderSo the site has a permanent home on your computer.

  1. Before unzipping, right-click the zip file, choose Properties, tick Unblock at the bottom (if it's there) and press OK. This stops Windows being suspicious of the files inside.
  2. Make a folder for websites, for example C:\Users\your name\Sites. Open File Explorer, go to your user folder (the one containing Documents and Downloads) and create a new folder called Sites.
  3. Right-click the zip, choose Extract All…, and extract it into that Sites folder. You should end up with the site folder (called billbeacham.com in the zip). Once the site is on GitHub you'll swap this for a copy from GitHub Desktop: see step 8.

Why not Documents or the Desktop? On many Windows computers those folders are synced to OneDrive. The site's tools create thousands of small files, and OneDrive syncing them slows everything down and can cause errors.

2. Install Node.jsThe engine that builds and previews the site. You never need to open it directly.

  1. Go to nodejs.org and download the LTS version for Windows (the Windows Installer (.msi)). LTS means "long-term support", the steady version.
  2. Run the installer and click Next through it, accepting the defaults.
  3. On the screen titled Tools for Native Modules, leave the box unticked. The site doesn't need those extra tools.
  4. When it finishes, restart your computer. Windows only notices newly installed tools after a restart.

3. Install VS CodeA free editor from Microsoft for the posts (Markdown), the games list (JSON) and the page files (.astro).

  1. Go to code.visualstudio.com and click Download for Windows.
  2. Run the installer. On the Select Additional Tasks screen, tick Add "Open with Code" action to Windows Explorer directory context menu. That lets you right-click the site folder and open it straight in VS Code.
  3. Open VS Code, choose File → Open Folder… and pick the site folder. If it asks "Do you trust the authors of the files in this folder?", choose Yes, I trust the authors.
  4. A message will pop up in the bottom right recommending the Astro extension. Click Install. It colours and checks the .astro page files. (If you miss the message: click the four-squares icon on the left, search for Astro, and install the one by Astro.)

4. Preview the siteThis is the bit you'll do every time.

  1. In the site folder, double-click Preview the site.bat.
  2. If Windows shows a blue box saying "Windows protected your PC", click More info, then Run anyway. It only asks once.
  3. A black window opens. The first time, it downloads the building blocks the site needs, which takes a minute or two. After that, it starts in a few seconds.
  4. Your web browser opens at http://localhost:4321. That's the site, running privately on your computer. Nobody else can see it.
  5. Leave the black window open while you work. Whenever you save a change in VS Code, the page in your browser updates by itself.
  6. When you've finished, close the black window to stop the preview.

Prefer VS Code's own terminal? In VS Code, choose Terminal → New Terminal and type npm run dev, then press Enter. Hold Ctrl and click the localhost:4321 link it shows. Press Ctrl+C in the terminal to stop it.

6. Making changes

Writing a new blog post

  1. In VS Code, open src/content/posts/, right-click _example.md and choose Copy, then right-click the posts folder and choose Paste.
  2. Rename the copy (right-click → Rename) to something short with hyphens, e.g. running-a-heist.md. This becomes the web address: /blog/running-a-heist/. Don't start the name with an underscore: files starting with _ are ignored.
  3. Edit the details at the top, between the two --- lines: 
    ---
title: "Running a heist"
date: 2026-12-01
kind: reflection      # reflection (in-depth) or journal (quick note)
summary: "One or two sentences for the list of posts."
tags: [tabletop]      # video-games and/or tabletop also show it on those pages; any other tag gets its own page
draft: false          # true hides it from the site
---
    For a journal entry you can also add a link: link: https://… and linkLabel: "What the link is".
  4. Write the note underneath. Blank lines separate paragraphs; ## A heading makes a subheading; *italics*, **bold** and [link text](https://…) work as you'd expect.
  5. Save (Ctrl+S) and look at localhost:4321/blog.

See it as you write: with a .md file open, press Ctrl+K then V to show a formatted preview beside it.

Editing the games list (JSON)

JSON is fussy about punctuation, so a few rules:

  • Text always goes in straight double quotes: "title": "Just Cause 4".
  • Items in a list are separated by commas, but there's no comma after the last one.
  • VS Code underlines mistakes with a red squiggle; hover over it to see what's wrong. If the preview window shows an error after you save, it's almost always a missing or extra comma.
  • To give a game the sliding panel, copy an existing "detail": { … } block from another game and edit it.

Changing wording on a page (.astro)

The part between the two --- lines at the top is code: best left alone. Below it, change only the words between tags, like <p>this text</p>. Leave anything in < > or { } as it is. If something breaks, Ctrl+Z undoes it.

Printing a picture in the site's colours

The Piranesi plates and the adventure covers are re-printed in the site's four inks (dark brown, rust, ochre and cream). You can do the same to any picture. It's a simple program, not AI, and it works best on engravings, woodcuts and line drawings; photos come out looking like screen prints.

  1. Put the original picture in a folder called originals inside the site folder (make it the first time), e.g. originals/my-cover.jpg.
  2. In VS Code, open the terminal (Terminal → New Terminal) and type: 
    npm run ink -- originals/my-cover.jpg
    The printed version is saved as public/art/my-cover.webp, ready to use as /art/my-cover.webp, for example as an adventure's cover.
  3. If it's too dark or too light, run it again with --light: a smaller number lightens it, a bigger one darkens it (it starts at 0.72), e.g. npm run ink -- originals/my-cover.jpg --light 0.6. --width 900 makes it smaller.
  4. Only use artwork that's public domain or yours, and credit the artist.

7. If something goes wrong

What you seeWhat to do
Yellow "npm warn" lines during the first runHarmless. As long as the browser opens afterwards, ignore them.
"Node.js is not installed yet"Install Node.js (step 2), then restart the computer.
"'npm' is not recognized…"Same: restart the computer after installing Node.js.
"…running scripts is disabled on this system" (in VS Code's terminal)Use Preview the site.bat instead, or in VS Code click the small ⌄ next to the + above the terminal and choose Command Prompt.
The browser says the site can't be reachedCheck the black preview window is still open. If you closed it, double-click the .bat file again.
A red error page in the browser after savingIt names the file and line. Usually a missing comma in JSON or a deleted --- or quote mark in a note. Fix it and save again.
"Port 4321 is in use"An old preview is still running. Close all black preview windows and try again.
The preview keeps showing an old versionClose the preview window, delete the .astro folder inside billbeacham.com, and start the preview again.

8. Publishing your changesYour copy on GitHub is the website: send changes there and moonbeach.uk updates itself.

The site lives in a public GitHub repository. Every time you send ("push") changes to it, GitHub rebuilds the site and publishes it to moonbeach.uk, usually within two minutes. You do this with GitHub Desktop, a free app with buttons rather than commands.

Once: get your copy from GitHub

  1. Install GitHub Desktop and sign in with the GitHub account Jeni set up for you.
  2. Choose File → Clone repository…, pick moonbeach.uk from the list, and set the Local path to your Sites folder (not Documents or the Desktop, as in step 1). Click Clone.
  3. From now on, work in this new folder: open it in VS Code and run Preview the site.bat from it. The first preview downloads the building blocks again, as before. The old unzipped folder can then be deleted.

Every time: publish what you've changed

  1. Make your changes and check them in the preview as usual.
  2. Open GitHub Desktop. The left-hand list shows every file you've changed; click one to see exactly what's different.
  3. Bottom left, type a short note in Summary, e.g. New journal post: The Hidden Isle, and click Commit to main.
  4. Click Push origin at the top. That's it: the site updates in a minute or two.

Not ready to publish a post? Leave draft: true at the top. It's saved to GitHub but stays off the site. Because the repository is public, though, anyone looking at GitHub itself could read a draft: keep anything truly private off it.

Did it work? On GitHub, the repository's Actions tab shows each publish: a green tick means it's live; a red cross means the build failed (usually a mistake in a post's details) and the old version stays up. Run the preview, fix whatever it complains about, and push again.

Working on two computers? Click Fetch origin (then Pull) in GitHub Desktop before you start, to get the latest version.

9. Optional extras

A nicer place to write

VS Code does everything the site needs. If you'd like a calmer writing space for the posts themselves, Obsidian is free and works well: install it, choose Open folder as vault, and pick the src\content folder inside the site folder. It shows each note's details (title, date, kind…) as a tidy form at the top. Use it only for the .md files; keep using VS Code for the games list and the pages.

Keeping a backup

GitHub keeps every version of every file you've pushed, so it is your backup: in GitHub Desktop, History shows each change, and any of them can be undone. The only things not on GitHub are the private folders kept out on purpose (inspiration and originals); back those up separately if you use them.
